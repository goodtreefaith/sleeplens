# Contributing to SleepLens

SleepLens helps CPAP users understand their machine's data. Useful contributions
include clearer explanations, accessible controls, parser tests and support for
more machines. You do not need therapy data to get started.

## Pick a starting point

- Improve an explanation in `app/src/lib/glossary.ts`.
- Reproduce a bug using the bundled synthetic card or browser sample mode.
- Add a test for a parser edge case with generated bytes.
- Propose a machine parser after reading the [format notes](docs/FORMAT_NOTES.md)
  and [shared data model](docs/APP_CONTRACT.md).

For a new parser or a substantial UI change, open an issue first so we can
agree on the scope. Keep a pull request focused on one change.

## Set up

Clone the repository and install Node.js 20+ and a stable Rust toolchain.
Desktop development also needs the [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/).

```bash
git clone https://github.com/goodtreefaith/sleeplens.git
cd sleeplens
npm ci
npm --prefix app ci
```

Run `npm --prefix app run dev` for the React interface with synthetic browser
data. For native card import and SQLite storage, follow the
[macOS build instructions](README.md#build-for-macos).

## Find your way around

| Path | Purpose |
| --- | --- |
| `crates/sleeplens-core/` | Rust parsers, data model and metrics |
| `crates/sleeplens-cli/` | Read-only command-line card inspector |
| `app/src-tauri/` | Desktop commands, local storage and imports |
| `app/src/` | React interface, glossary and charts |
| `src/`, `tools/`, `tests/` | TypeScript reference parser and inspection tools |
| `fixtures/synthetic-as2x/` | Generated test card with fake identifiers and 2030 dates |
| `demo/` | Standalone design demo with made-up data |

## Check your change

Choose checks for the code you changed. Run these from the repository root:

```bash
# Rust core, CLI and desktop backend
cargo test --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings

# TypeScript reference parser
npm test
npm run typecheck

# React interface and production frontend bundle
npm --prefix app test
npm --prefix app run build
```

For interface changes, inspect the rendered result with synthetic data in light
and dark themes. Check desktop layouts at 1920 and 1280 pixels and the minimum
960 × 640 app window. Exercise the controls you changed with the keyboard too.
Docs-only changes need a rendered review and working links, not a full rebuild.

In your pull request, explain the user-visible result and record which checks
passed. Say which checks you could not run.

## Keep therapy data private

Use synthetic data in public issues, pull requests, screenshots and fixtures.
Do not upload SD-card archives, real `.dat`, `.bkp` or `.edf` files, local
databases, patient details or device serial numbers. File and folder names may
contain serials too. Replace those with placeholders before sharing a layout.

The `.gitignore` is a convenience, not a privacy check. Inspect your staged
diff and new files before committing. The checked-in card fixture is synthetic;
regenerate it with `npm run make-fixture`. Do not substitute a real card.

Both inspectors read a supplied folder without modifying it:

```bash
cargo run -p sleeplens-cli -- inspect fixtures/synthetic-as2x
npm run inspect -- fixtures/synthetic-as2x
```

Use that fixture for public examples. Review any output from a real card locally
and keep it out of public reports, even if the inspector masks the serial.

## Preserve the meaning of the data

Keep machine-reported values distinct from values SleepLens computes. Show
missing data as missing, preserve units and label estimates. A sleep score or
breathing-based stage estimate must not imply clinical validation. Do not add
advice to change prescribed settings.

For parser work, document assumptions and uncertain fields in the format notes.
Keep network calls and remote assets out of the desktop app.
